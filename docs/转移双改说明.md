# 转移双改说明（当日锁死）

- 产品：档期预订（09-slotbook）
- 锁定日期：2026-11-21
- 适用接口：`POST /api/transfer`
- 口径常量：`backend/transfer_svc.py::TRANSFER_WRITE_PATH = "A_same_transaction_double_write"`

## 一、结论：只走路径 A

跨档迁移的正确性口径**只能二选一**，两边不得混用。本产品当日钉死为：

> **路径 A：同一事务内释源 + 占目标。任一步失败则两边同滚，源仍占、目标零增。**

放弃路径 B（先写转移影子、再原子释源占目标），也不得在路径 A 里夹带影子表、影子任务或“先刷目标档、稍后补释源”的半截写法。

## 二、禁止事项

1. **禁止只刷目标档展示**：只把目标档 `booked` 加上、或只改 `bookings.slot_id`，而不在同一事务里扣减源档 `booked`，即为半截写入，直接判失败。
2. **禁止混用**：运行期若检测到下列任一情况，记为 **转移双改偏航**（audit action `transfer_double_write_deviation`）并拒绝写入（409），两边零改：
   - 环境变量 `SLOTBOOK_TRANSFER_PATH` 被改成非 `A_same_transaction_double_write` 的值；
   - 运行库中出现路径 B 的 `transfer_shadow` 表。
3. 不得用“事务外删源、事务内插目标”这类跨事务拆写代替。

## 三、路径 A 的写入顺序

1. 先按 `booking:{id}`、`slot:{源档}`、`slot:{目标档}` 排序抢档锁；后到者只写 `contention_log`，不写业务。
2. `BEGIN IMMEDIATE`，以下全部在同一事务：
   - `UPDATE slots SET booked = booked - 席位 WHERE id=源档 AND booked >= 席位`，影响行数必须为 1；
   - `UPDATE slots SET booked = booked + 席位 WHERE id=目标档 AND booked + 席位 <= capacity`，影响行数必须为 1；
   - 目标档余席校验须扣除目标档 `占位中` 的 holds（`capacity - booked - pending >= 席位`）；
   - `UPDATE bookings SET slot_id=目标档, snapshot_gen=目标档 generation`；
   - 写 `transfer_jobs`（状态 `已转移`，备注标明路径 A）与 `audit_trail`（`booking_transfer`，含源/目标/席位/前后盘面）。
3. `COMMIT`。任一步抛错则 `ROLLBACK`，源档仍占、目标档零增、正式册仍留源档。
4. 事务提交后释放档锁；失败路径先回滚业务，再释放本次新抢到的锁。

## 四、五处同态

一次成功转移后，下列五处必须同时成立且相互可对：

| 处 | 口径 |
|----|------|
| 源占位 | 源档 `booked` 减少席位数；源档不再包含该正式册 |
| 目标占位 | 目标档 `booked` 增加席位数；正式册归目标档 |
| 余席 | `capacity - booked - 占位中 holds`，源增目标减，总占位不虚高 |
| 对账 | 每档 `bookings(已确认).seats` 之和 == `slots.booked`，`all_ok` |
| 审计 | `audit_trail` 的 `booking_transfer` 与 `transfer_jobs.已转移` 同源同席位 |
